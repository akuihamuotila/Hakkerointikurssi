```message``` on funktion parametri ja sen arvo on ```0x0```

0x0 on muistiosoite
0x = heksadesimaalimuoto
0 = arvo

eli osoite: 0

osoite 0 on NULL

eli 0x0 on NULL pointer

tiiviisti:

```message = 0x0``` tarkoittaa:

Pointer sisältää arvon 0

0 ei ole laillinen muistialue (se on NULL alue, joka jätetään tyhjäksi)

```message``` yrittää lukea osoitteesta 0

CPU estää sen

Ongelma on siis lyhyesti seuraava:

-> Funktio print_scrambled yrittää lukea pointerin message kautta muistia tarkistamatta, onko se NULL.

-> main kutsuu funktiota NULL-osoittimella.

-> Kun ohjelma yrittää käyttää NULL-osoitetta, se kaatuu

Korjaus:

alkuperäinen koodi:
```C
#include "stdio.h"

void print_scrambled(char *message)
{
  register int i = 3;
  do {
    printf("%c", (*message)+i);
  } while (*++message);
  printf("\n");
}

int main()
{
  char * bad_message = NULL;
  char * good_message = "Hello, world.";

  print_scrambled(good_message);
  print_scrambled(bad_message);
}
```

Lisään kooodin alkuun pätkän, joka varmistaa, että jos ```message``` on NULL, funktio palaa heti alkuun, eikä pääse ongelmakohtaan:
```C
{
  if (message == NULL) {
    printf("Error: message is NULL\n");
    return;
  }
```

Korjattu koodi:
```C
#include "stdio.h"

void print_scrambled(char *message)
{
  if (message == NULL) {
    printf("Error: message is NULL\n");
    return;
  }
  
  register int i = 3;
  do {
    printf("%c", (*message)+i);
  } while (*++message);
  printf("\n");
}

int main()
{
  char * bad_message = NULL;
  char * good_message = "Hello, world.";

  print_scrambled(good_message);
  print_scrambled(bad_message);
}
```

Linux x86_64 -kutsukäytännössä funktion argumentit annetaan rekistereissä:

Ensimmäinen argumentti -> ```rdi```

Toinen argumentti -> ```rsi```

```main``` kutsuu ```mAsdf3a``` näin:

```0x... <+123>: call 0x... <mAsdf3a>```

Eli juuri ennen tuota kutsua:

```$rdi``` sisältää osoitteen ensimmäiseen merkkijonoon (tarkistuksen “avain” tai vertailupohja)

```$rsi``` sisältää osoitteen toiseen merkkijonoon (käyttäjän syöte / bufferi)

Siksi ```$rdi``` on järkevä tarkistaa heti breakpointissa.

Tein näin:

```set $buf = $rdi```  
  Tallennan muuttujaan ```$buf``` sen osoitteen, joka oli rekisterissä ```$rdi```.

```$buf``` on GDB:n oma convenience variable, eli väliaikainen nimi, johon voit tallentaa jonkin arvon, jotta sitä on helpompi käyttää myöhemmin.

```x/s $buf```  
  ```x/s``` tulkitsee muistiosoitteen sisällön C-merkkijonona (string), eli tulostaa merkit kunnes vastaan tulee ```\0```.

```bash
0x... <+63>: add $0x3,%edx
```

```test $0x1,%al``` tarkistaa onko indeksi parillinen vai pariton:

jos indeksi on parillinen, ```je``` hyppää add-haaraan -> ```add $0x3,%edx```

jos indeksi on pariton, hyppyä ei tapahdu -> ```sub $0x7,%edx```

Lisäksi ```jmp``` varmistaa, että vain toinen (add tai sub) suoritetaan per merkki.

```mAsdf3a``` ottaa kaksi merkkijonoa ja käy ne läpi indeksillä ```i``` (rekisteri ```%rax``` toimii laskurina).

Se lukee molemmista yhden merkin ja vertailee:

vertailumerkki tulee osoitteesta ```%rbp``` (ensin ```mov %rdi,%rbp```)

käyttäjän merkki tulee osoitteesta ```%rbx``` (ensin ```mov %rsi,%rbx```)

vertailu tehdään rivillä ```cmp %ecx,%edx```

Koska koodi muokkaa vertailumerkkiä (```%edx```) ja vertaa sitä käyttäjän merkkiin (```%ecx```), sääntö on:

jos indeksi on parillinen: käyttäjän merkki = vertailumerkki + 3

jos indeksi on pariton: käyttäjän merkki = vertailumerkki - 7
