## x)

- "Low hanging fruit" ```strace``` ja ```ltrace``` ohjelma kannattaa ajaa näiden kanssa, koska siten voi helposti löytyä haavoittuvuuksia.

- Jos binääri on stripped Ghidra on pakollinen, tämän voi nähdä ```file``` komennolla.

- Se, että se on stripped tarkoittaa, että funktioiden oikeat nimet on poistettu ja debug-tiedot on poistettu, eli et voi helposti nähdä mikä funktio tekee mitä

- Ghidra tekee koodista inhimillisempää, eli helpommin luettavaa

- Tarkemmin Ghidra siis muuntaa konekoodin C:tä muistuttavaksi pseudokoodiksi -> Tämä tekee ohjelman kulusta ymmärrettävän.

- Tulostaa: ```"What's the password?"```

```__isoc99_scanf(&DAT_0010201d,?password);```

- Vertailee syötettä kovakoodattuun salasanaan:
```iVar1 = strcmp(?password,"piilos-AnAnAs");```

- Jos vertailu palauttaa 0 (eli syöte on oikein)(```if (iVar1 == 0)```), ohjelma tulostaa onnistumisviestin ja flagin:
```Yes! That's the password. FLAG{Tero-0e3bed0a89d8851da933c64fefad4ff2}```

```Sorry, no bonus.```

```piilos-AnAnAs```

## c)

Siirryin terminaalissa ```passtr``` -kansioon

Ajoin ohjelman komennolla ```./passtr``` tuttuun tapaan kysyy salasanaa

Tuttuun tapaan Ghidrassa uusi projekti ja importataan passtr ja analysoidaan defaulteilla

```passtr``` decompile main:
```
undefined8 main(void)

{
  int iVar1;
  char local_28 [32];
  
  puts("What\'s the password?");
  __isoc99_scanf(&DAT_0010201d,local_28);
  iVar1 = strcmp(local_28,"sala-hakkeri-321");
  if (iVar1 == 0) {
    puts("Yes! That\'s the password. FLAG{Tero-d75ee66af0a68663f15539ec0f46e3b1}");
  }
  else {
    puts("Sorry, no bonus.");
  }
  return 0;
}
```
painan hiirellä ```strcmp``` -kohtaa

Listing ikkuna menee tähän näkymään
```
        00101196 48 89 d6        MOV        RSI=>s_sala-hakkeri-321_00102022,RDX             = "sala-hakkeri-321"
        00101199 48 89 c7        MOV        RDI,RAX
        0010119c e8 9f fe        CALL       <EXTERNAL>::strcmp                               int strcmp(char * __s1, char * _
                 ff ff
        001011a1 85 c0           TEST       EAX,EAX
        001011a3 75 11           JNZ        LAB_001011b6
        001011a5 48 8d 05        LEA        RAX,[s_Yes!_That's_the_password._FLAG{T_001020   = "Yes! That's the password. FLA
                 8c 0e 00 00
        001011ac 48 89 c7        MOV        RDI=>s_Yes!_That's_the_password._FLAG{T_001020   = "Yes! That's the password. FLA
```
Klikkaan rivin  ```001011a3 75 11           JNZ        LAB_001011b6``` aktiiviseksi ja right klikkaan ja painan ```Patch instruction```

Teen muutoksen ```JNZ -> JZ```
```JNZ``` on "jump if not zero"
```JZ``` on "jump if zero"

"Zero" vastaus tulee kun salasana menee oikein ja silloin ohjelma normaalisti ei hyppää tuon "yes / FLAG" -kohdan yli vaan printtaa sen, mutta jos vastaus on jotain muuta kuin "zero" tai siis nolla niin silloin se hyppää tuon yli seuraavaan vaiheeseen, eli siihen, että salasana ei mennyt läpi.

Nyt kun muutamme sen "jump if zero" eli "JZ" muotoon, kun salasana menee väärin ja vastaukseksi tulee muuta kuin nolla, se ei hyppää "yes / FLAG" -kohdan yli vaan printtaa sen. Eli kun salasana menee oikein ja vastaukseksi tulee nolla, se hyppää tuon yli ja printtaa, että väärä salasana.

eli yksinkertaisesti:
```
Ennen patchia: JNZ LAB_001011b6  -> väärä salasana hyppää "Sorry" haaraan
Patchin jälkeen: JZ LAB_001011b6 -> oikea salasana hyppää "Sorry" haaraan
```

Exportoin patchatyn binäärin: File -> Export program -> exportasin sen passtr kansioon nimellä ```passtr-patched``` original file formaatissa.

Annoin itselleni oikeudet ajaa sen ```chmod +x passtr-patched```

Ajoin tiedoston komennolla ```./passtr-patched``` ja käytin omaa keksimääni -> tietenkin väärää salasanaa

Tuloste:
```
What's the password?
hackerman
Yes! That's the password. FLAG{Tero-d75ee66af0a68663f15539ec0f46e3b1}
```
Kokeillaan vielä oikealla salasanalla

Tuloste:
```
$  ./passtr-patched
What's the password?
sala-hakkeri-321
Sorry, no bonus.
```

Tehtävä suoritettu ja logiikka käännetty ympäri.
